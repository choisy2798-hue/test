# 저장 기능 전면 개편 (요청하신 데이터 구조로 재구성)

## 적용된 데이터 구조
```js
appData = {
  user: { name },
  medications: [ {id, name, dose, slots, prescriptionDate, totalDays}, ... ],
  medicationRecords: {
    "2026-10-02": { morning:"taken", noon:"missed", evening:"taken" },
    "2026-10-03": { morning:"taken", noon:"taken", evening:"missed" },
    ...
  },
  settings: {
    times, slotLabels,           // "복약 알림 이름"(예: 아침 혈압약) + 시간
    soundAlert, familyAlert,
    preReminderEnabled, preReminderOffset, repeatAlarmEnabled,
    fontSize,
  },
  reasons: { evening: "forget_time" },   // 복약 누락 원인
  consultRequested: false,
  meta: { medIdSeq, lastActiveDate, missedNotified, alarmedSlots, repeatCounts, notifLog }
}
```
`localStorage` 키 `onulHaenaesseoyoAppData_v1`에 `JSON.stringify`로 저장하고, 불러올 때 `JSON.parse` 후 필드별로 안전하게 검증하며 적용합니다.

## 요청하신 항목 반영 현황
| 항목 | 반영 위치 |
|---|---|
| 사용자 이름 | `user.name` |
| 등록한 약 이름 | `medications[].name` |
| 복약 알림 이름 | `settings.slotLabels` — 설정 > 복약 알림 설정에서 "아침" → "아침 혈압약"처럼 직접 수정 가능 (새 입력칸 추가) |
| 복약 알림 시간 | `settings.times` |
| 복약 완료/미완료 상태 | `medicationRecords[오늘 날짜]` — 체크할 때마다 즉시 저장 |
| 날짜별 복약 기록 | `medicationRecords` — 날짜가 바뀌면 전날 기록을 자동 확정, 과거 기록은 계속 누적 |
| 복약 누락 원인 | `reasons` |
| 복약 이행률 | 저장값이 아니라 `medicationRecords`로부터 매번 자동 재계산 (별도 저장 안 함 — 항상 최신 기록 기준) |
| 보호자 알림 ON/OFF | `settings.familyAlert` |
| 기타 설정(글자크기, 사전알림, 반복알림, 음성알림 등) | `settings` |

## 저장 방식 (요청 1~6번 전부 반영)
1. 입력/수정 즉시 저장 — 이름, 약 등록/삭제, 알림 이름, 시간, 복약 체크, 누락 원인, 보호자 알림 등 모든 변경 핸들러에서 바로 `saveState()` 호출
2. 새로고침 시 `loadState()`로 복원
3. 앱 재실행 시에도 동일하게 복원 (서비스워커/브라우저 종료 여부와 무관)
4. 기존 저장 데이터가 있으면 초기화하지 않음 — `loadState()`는 항상 기존 값 위에 "있는 필드만" 덮어씀
5. 수정 시 해당 필드만 새 값으로 갱신 (덮어쓰기)
6. 삭제(약 삭제 등) 시 배열/객체에서 실제로 제거 후 즉시 재저장

## 오류 처리 (흰 화면 방지)
- `loadState()` 전체를 `try/catch`로 감싸, JSON이 손상되어도 예외가 밖으로 나가지 않고 기본값으로 계속 진행합니다.
- 저장된 구조에 없는 필드/다른 타입이 와도 `typeof` 체크 후에만 적용하므로, 구조가 일부 바뀌어도 나머지 필드는 안전하게 유지됩니다.
- **구버전(이전 저장 구조, 키 `onulHaenaesseoyoState_v1`) 데이터 자동 마이그레이션**: 새 키에 데이터가 없고 구버전 키에 데이터가 있으면, 그 값을 읽어 새 구조로 변환해 즉시 재저장합니다. 기존 사용자가 쓰던 기록이 사라지지 않습니다.

## 전체 데이터 삭제
설정 하단에 **"🗑️ 전체 데이터 삭제"** 메뉴를 추가했습니다. 누르면
> 저장된 모든 복약 기록과 설정을 삭제하시겠습니까? [취소] [확인]

확인을 눌러야만 실제로 삭제되고, 취소하면 아무 일도 일어나지 않습니다. 삭제 후에는 앱이 처음 설치한 상태(이름 "어르신", 약 없음, 알림 이름 기본값)로 돌아갑니다.

## 기존 기능과의 연결 확인
다음 기능 모두 저장 기능과 정상적으로 연결되어 작동합니다 (코드 레벨에서 직접 실행 검증함):
- 약 등록 / 수정 / 삭제
- 복약 알림 이름 수정 ← 이번에 새로 추가된 입력 UI
- 복약 시간 수정
- 복약 완료 기록
- 복약 누락 기록 (시간 경과 시 자동 감지되어 `medicationRecords`에 기록)
- 누락 원인 기록
- 복약 이행률 (저장된 `medicationRecords` 기반 자동 계산 — 건강정보 탭의 "복약 패턴 분석", "약사 상담 제안"도 동일한 데이터로 연결되어 정상 작동)
- 보호자 알림 설정
- 약사 상담 제안

## 직접 수행한 테스트 결과
요청하신 8단계 테스트를 실제 앱 코드(app.js)를 그대로 실행하는 방식으로 검증했습니다 (Node.js 샌드박스에서 실제 저장/로드 함수를 호출 — 화면 UI만 생략하고 로직은 100% 동일한 코드로 테스트).

1. 약 이름("혈압약") 등록 → 저장됨 ✅
2. 복약 알림 이름("아침" → "아침 혈압약") 수정 → 저장됨 ✅
3. 복약 시간("08:00" → "08:30") 수정 → 저장됨 ✅
4. 복약 완료 기록(아침 체크) → `medicationRecords`에 즉시 기록됨 ✅
5. 누락 원인("약 먹는 시간을 잊음") 입력 → 저장됨 ✅
6~7. 새로고침 / 앱 재실행(완전히 새로운 실행 환경으로 재시뮬레이션) ✅
8. 재실행 후 모든 값이 그대로 남아있음을 확인 — 이름, 약 목록, 알림 이름, 시간, 복약 완료 상태, 누락 원인, 보호자 알림, 복약 이행률(자동 재계산) 전부 정상 ✅

추가로 다음도 함께 검증했습니다:
- 전체 데이터 삭제 → 기본값으로 정확히 초기화 ✅
- 구버전 저장 데이터 자동 마이그레이션 ✅
- 손상된 JSON 데이터로부터 예외 없이 기본값 복구(흰 화면 방지) ✅

## 기존 UI/기능 유지
이번 작업은 저장 계층(데이터 읽기/쓰기)만 재구성했습니다. 화면 구성, 탭 구조, 디자인, 푸시 알림 기능은 그대로입니다. 유일한 화면 변화는 두 가지입니다:
- 설정 > 복약 알림 설정에 각 시간대별 **"알림 이름"** 입력칸 추가
- 설정 하단에 **"전체 데이터 삭제"** 메뉴 추가
