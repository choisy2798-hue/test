# 음성 복약 알림 기능 추가 — 분석 및 구현 보고서

## 0. 먼저 분석한 결과 (요청하신 "1. 현재 기능 먼저 분석")

| 확인 항목 | 결과 |

| 현재 기본 알림 구조 | 앱이 열려 있을 때: 로컬 타이머 기반 소리+음성+토스트. 앱이 닫혀 있어도: 서버가 보내는 **시스템 푸시 알림**(글자 안내)은 이미 와 있었음. 다만 이 푸시에는 **음성이 연결되어 있지 않았음** |

즉, "화면이 꺼져 있어도 글자 알림이 오는 구조"는 이미 있었고, 이번 작업은 **그 구조에 음성을 최대한 연결**하는 작업입니다. 기존 구조를 새로 만들지 않고 그대로 확장했습니다.

## 1. 수정한 파일
- `public/app.js` — 음성 전용 ON/OFF 설정 추가, 음성 테스트 버튼 정리, 알림 탭 시 음성 재생 처리, Service Worker 메시지 수신 처리
- `public/sw.js` — 푸시 수신 시 열려있는 페이지에 음성 재생 요청 전달, 알림 클릭 시 음성 문구를 담아 앱 열기
- `server.js` — 푸시 발송 시 음성 중복방지에 필요한 정보(슬롯/시각/음성 문구)를 함께 전송하도록 확장

CSS/디자인, 홈/복약체크/기록/건강정보/설정 화면 구조는 전혀 건드리지 않았습니다. 설정 화면에 토글 1개 + 버튼 문구 수정만 추가됐습니다.

## 2. 추가한 음성 알림 기능
- **🔊 음성 복약 알림 ON/OFF** (기본값 ON, `localStorage`에 `voiceReminderEnabled`로 저장) — 기존 차임벨 소리(`soundAlert`)와 완전히 분리된 별도 토글
- **🔊 음성 알림 테스트** 버튼 — 누르면 토글 상태와 무관하게 즉시 "약 먹을 시간입니다" 재생
- 복약 시간이 되면: 앱이 열려 있으면 기존처럼 소리+음성 즉시 재생
- **새로 추가**: 시스템 알림을 **탭해서 앱이 열릴 때**, 열리자마자 자동으로 "약 먹을 시간입니다" 음성이 재생됨 (화면이 꺼져 있었거나 앱이 완전히 종료돼 있었어도 동작)
- **새로 추가(최선 노력)**: 앱이 백그라운드에 있지만 완전히 종료되지 않은 상태에서 푸시가 도착하면, 열려 있는 페이지로 즉시 음성 재생을 시도함 (보장되지는 않음 — 아래 3번 참고)
- 날짜+슬롯+시각 기준 고유 키로 음성 중복 재생 방지 (로컬 타이머와 푸시 두 경로가 동시에 작동해도 한 번만 재생)

## 3. 음성 알림이 작동하는 조건 (정확한 구분)

| 상황 | 시스템 알림(글자) | 음성("약 먹을 시간입니다") |
|---|---|---|
| **A. 웹페이지를 열어둔 상태** | ✅ 항상 | ✅ 항상, 자동으로 즉시 재생 |
| **B. PWA를 설치했고, 다른 앱 사용 중 (화면은 켜짐)** | ✅ 항상 (서버 푸시) | 🟡 **최선 노력** — 페이지가 아직 살아있으면 재생 시도하지만 OS가 백그라운드 탭의 스크립트를 일시 정지시키면 안 될 수도 있음. **탭하면 100% 재생** |
| **C. 화면이 완전히 꺼진 상태** | ✅ 항상 (서버 푸시, 화면을 켬) | ❌ 화면이 꺼진 채로 자동 음성은 **불가능**. 알림을 눌러서 화면을 켜고 앱이 열리는 순간 재생 |
| **D. 음성 알림 OFF** | ✅ 항상 | ❌ 의도적으로 재생 안 함 (차임벨/글자 알림은 유지) |
| **E. 음성 테스트 버튼** | — | ✅ 항상 즉시 재생 |

## 4. 백그라운드에서 작동하는 방식
1. 서버(`server.js`)가 설정된 시각이 되면 Web Push로 기기에 직접 알림을 보냅니다 (앱이 꺼져 있어도 OS가 대신 받아줍니다).
2. `sw.js`(Service Worker)가 그 푸시를 받아 **시스템 알림을 띄우고**, 동시에 **열려 있는 페이지가 있는지** 확인해서 있으면 "지금 음성 재생해줘"라는 메시지를 보냅니다.
3. 사용자가 그 알림을 **탭하면**, 앱이 열리면서 주소 뒤에 음성 문구를 실어 보내고, 앱이 켜지자마자 그 문구를 읽어줍니다.
4. 이미 같은 복약 시간에 대해 음성이 재생된 적이 있으면(로컬 타이머든 푸시든) 다시 재생하지 않습니다.

## 5. iPhone에서 가능한 범위
- iOS 16.4 이상 + **홈 화면에 추가한 상태**에서만 푸시 자체가 옵니다 (이건 기존 기능과 동일).
- 화면이 켜져 있고 앱이 열려 있으면: 음성 100% 재생.
- 화면을 끄거나 다른 앱을 쓰는 동안: **시스템 알림(글자)만** 옵니다. 음성은 **그 알림을 탭해서 앱을 여는 순간** 재생됩니다.
- 화면이 꺼진 채로 탭 없이 자동으로 음성만 흘러나오는 것은 **iOS 정책상 불가능**합니다 (아래 7번 참고).

## 6. Android에서 가능한 범위
- 전반적으로 iOS보다 백그라운드 허용 범위가 넓은 편이라, 앱을 다른 화면으로 전환한 직후(완전히 종료되지 않은 상태)라면 음성이 자동으로 들릴 가능성이 iPhone보다는 조금 더 있습니다. 그러나 이것도 기기 제조사의 배터리 최적화 정책에 따라 언제든 꺼질 수 있어 **보장되지는 않습니다.**
- 화면이 꺼진 상태에서 자동 음성 재생이 불가능한 것은 Android도 동일합니다.
- 확실하게 음성을 들으려면 iPhone과 마찬가지로 **알림을 탭**하는 것이 가장 안정적입니다.

## 7. 현재 웹 기술의 한계 (반드시 알려달라고 하신 부분)
**"화면이 꺼진 상태에서 아무것도 누르지 않아도 자동으로 음성이 나오는 것"은 현재 웹 기술로 불가능합니다.** 이건 이 사이트만의 문제가 아니라 다음과 같은 구조적인 이유 때문입니다.
- `speechSynthesis`(음성 API)는 **Service Worker 안에서는 아예 존재하지 않습니다.** 반드시 열려 있는 페이지(Window)가 있어야만 음성을 재생할 수 있습니다.
- 화면이 꺼지거나 앱이 완전히 백그라운드로 가면, iOS/Android 공통으로 OS가 그 페이지의 JavaScript 실행을 일시정지하거나 종료시킵니다.
- 이것은 특정 코드를 더 잘 짠다고 우회할 수 있는 부분이 아니라, 브라우저/운영체제 차원의 보안·배터리 정책입니다.

### 질문하신 5가지 방법 중 추천
1. **PWA + Web Push** ← **이미 적용되어 있고, 가장 현실적인 방법입니다.** (이번에 음성 연결까지 확장함)
2. Service Worker + 시스템 알림 ← 1번과 사실상 같은 구조 (이미 포함됨)
3. iOS 단축어/자동화 연동 ← 웹사이트만으로는 트리거하기 어렵고, 사용자가 수동으로 단축어를 등록해야 해서 번거로움. 비추천
4. 별도 모바일 앱 개발(네이티브) ← **"화면이 꺼진 상태에서도 100% 자동 음성"이 정말 필요하다면 이것이 유일한 완전한 해결책**입니다. 네이티브 앱은 OS의 로컬 알림 예약 기능을 이용해 화면이 꺼진 상태에서도 소리/음성을 재생할 수 있는 권한을 가질 수 있습니다. 다만 개발 비용·심사 과정이 추가로 필요합니다.
5. 기타 — 없음

**결론: 지금 적용한 "Web Push + 탭하면 즉시 음성" 구조가, 추가 비용 없이 적용 가능한 범위에서 가장 현실적인 최선입니다.** "화면이 꺼진 채로 탭 없이" 음성이 꼭 필요하다면 4번(네이티브 앱)으로 가야 합니다.

## 8. 실제 휴대폰에서 테스트하는 방법 (요청하신 테스트 1~5)
배포 후(Render 등) 홈 화면에 추가한 상태에서:

1. **테스트 1 (화면 열어둠)**: 복약 시간을 1분 뒤로 설정 → 앱을 열어둔 채 기다리기 → 시스템 알림 + 음성 둘 다 나오는지 확인
2. **테스트 2 (백그라운드, 화면 켜짐)**: 복약 시간을 1분 뒤로 설정 → 앱을 연 뒤 다른 앱으로 전환 → 알림이 오는지, 음성이 혹시 들리는지(된다면 보너스, 안 돼도 정상) 확인
3. **테스트 3 (화면 꺼짐)**: 복약 시간을 1분 뒤로 설정 → 화면 끄기 → 진동/알림이 오는지 확인 → 화면을 켜고 **알림을 탭** → 앱이 열리며 음성이 나오는지 확인
4. **테스트 4 (음성 OFF)**: 설정 > 복약 알림 설정에서 음성 토글 끄기 → 복약 시간 도달 → 알림은 오지만 음성은 안 나오는지 확인
5. **테스트 5 (테스트 버튼)**: 설정 > 복약 알림 설정 > "🔊 음성 알림 테스트" 버튼 클릭 → 즉시 음성이 나오는지 확인

> 참고: 테스트 전에 설정 > 복약 알림 설정에서 **"🔔 이 기기로 푸시 알림 받기"**가 켜져 있어야 2·3번 테스트가 의미 있어요 (이전 작업에서 추가된 기능).

---
배포는 기존과 동일합니다 (Render 등에 올린 뒤 Deploy만 다시 누르면 반영돼요). 서버 쪽 코드(`server.js`)도 수정됐으니 **반드시 재배포**가 필요합니다.
